### 2.1　多源档案数据采集

智能管理的"原料"来自三类渠道，对应不同的采集策略与难点。

**1. 纸质档案数字化（存量数字化）。** 核心是将实体载体转为数字图像，再进一步转为可检索文本。采集方式包括：
- **扫描**：平板/馈纸式扫描仪，适合普通文书；强调分辨率（通常 ≥300 dpi）、色彩模式（黑白/灰度/彩色）、去阴影与纠偏。
- **非接触式采集**：书刊扫描台、缩微胶片数字化仪，避免拆装对珍贵档案造成损伤。
- **三维/大幅面采集**：书画、地图、舆图用大幅面扫描或摄影测量。

**2. 原生电子文件归档（增量电子化）。** 依托电子文件单套制管理，从业务系统直接捕获具备"四性"（真实性、完整性、可用性、安全性）的电子文件，避免"二次数字化"。关键是捕获**背景元数据**（形成者、业务背景、版本链）。

**3. 网络与社交媒体档案。** 包括网页归档（WARC 格式、Heritrix 抓取）、政务新媒体（微博/微信/短视频）留存。难点在于动态内容、版权与持续抓取策略。

> **智能交互（虚拟仿真）**：本部分配套"数字化全流程虚拟仿真"模块——学生可在仿真环境中操作扫描仪参数、体验 OCR 转写、观察不同分辨率对识别率的影响，系统实时给出"数据质量评分"。

### 2.2　OCR 与语音识别：从图像/声音到文本

OCR（光学字符识别）与 ASR（自动语音识别）是"图像/声音→文本"的关键跃迁，也是后续一切智能处理的前提。

**OCR 技术流程**：

```
原始图像 → 图像预处理(去噪/二值化/纠偏) → 版面分析(分栏/分块)
        → 文字识别(单行切分+字符识别) → 后处理(语言模型纠错/字典校正) → 结构化文本
```

**档案场景的特殊挑战**：
- **字体多样**：繁体竖排、碑刻、手写体、钢板刻印、旧式标点，识别率显著低于印刷体简体。
- **多语种混排**：满汉合璧、中英对照、少数民族文字。
- **版式复杂**：表格、批注、印章覆盖、粘连字。

**ASR 在档案中的应用**：口述史建档、会议录音转写、方言档案采录。讯飞语音识别在多方言、远场噪声场景下具备优势，可将口述档案转为可检索文本，并保留时间戳便于定位。

**实践示例（调用 OCR 接口完成样本转写）**：

```python
# 概念示例：调用 OCR 服务完成一张民国公文的转写（以开放平台接口为例）
from ocr_client import ArchiveOCR

client = ArchiveOCR(api_key="YOUR_KEY")
result = client.recognize(
    image_path="sample/min_guo_gongwen.jpg",
    options={
        "language": "chi_tra",      # 繁体中文
        "layout": "vertical",       # 竖排
        "seal_aware": True          # 印章区域单独标注，避免误并入正文
    }
)
print(result.text)            # 识别文本
print(result.confidence)      # 逐字置信度，用于质量评估
# 低置信度字符（<0.7）应回退人工校对，避免"garbage in"
```

> **讯飞知喻实践（专栏）**：讯飞知喻在多个省级档案馆落地"AI 档案大脑"，其 OCR 引擎针对历史档案做了繁体、手写、印章覆盖专项优化，可将民国档案批量转写效率提升数倍。课堂可演示同一页档案在"通用 OCR"与"档案专用 OCR"下的识别率差异。

### 2.3　数据清洗与标准化

转写得到的文本往往"脏"：错字、缺字、字段错位、日期格式不一。清洗的目标是让数据"可计算"。

- **去噪与纠错**：基于语言模型/词典对 OCR 低置信度字符做校正；对无法确定的字符保留占位符而非臆测。
- **去重**：基于 SimHash、文本相似度识别重复件、重份文件。
- **字段规整**：日期统一为 ISO 8601（如 `1948-05-12`）；人名、机构名按《中国档案分类法》与规范档（authority file）对齐。

### 2.4　元数据管理

元数据是档案"可被理解、可被信任、可被关联"的命脉。

**常用标准框架**：
- **都柏林核心（Dublin Core）**：15 个核心元素（题名、创建者、主题、日期等），通用但偏简。
- **DA/T 18《档案著录规则》**：国内档案著录的行业标准，规定著录项目与格式。
- **PREMIS**：数字保存元数据标准，记录保存事件、权限、技术环境，支撑长期可读。

**元数据自动抽取**：利用 NER（命名实体识别）从正文自动抽取题名、责任者、时间、地点，辅助著录，但仍需人工校验以保证凭证性。

> **AI 助教提问模板**："一份民国档案 OCR 识别错误率高达 15%，其中关键责任者姓名识别错误。在'效率'与'凭证准确性'之间应如何取舍？请设计兼顾两者的采集—校对流程。"

# 概念示例：用 PaddleOCR 批量转写档案扫描件并标记低置信度字符
from paddleocr import PaddleOCR
ocr = PaddleOCR(use_angle_cls=True, lang="ch")
for img_path in ["p1.jpg", "p2.jpg"]:
    result = ocr.ocr(img_path, cls=True)
    for line in result[0]:
        text, score = line[1][0], line[1][1]
        flag = "  <-- 需人工校对" if score < 0.7 else ""
        print(f"{img_path}\t{score:.2f}\t{text}{flag}")
```

### 2.8 多模态大模型 OCR 与文档理解：从字符识别到语义理解（V2.0）

传统 OCR 把图像变文字，但表格、手写、印章、骑缝常丢结构。V2.0 引入视觉语言模型做"文档理解"（来源：大模型多模态论文集、ai前沿技术、档案行业标准）：

| 对比 | 传统 OCR 流水线 | VLM 文档理解（mPLUG-DocOwl2 / UReader / Fox） |
|---|---|---|
| 输入 | 扫描页 → 单页 | 多页、高清、含表格/批注 |
| 输出 | 纯文本（丢版式） | 带结构的语义（表格、栏目、印章位置） |
| 手写/古体 | 依赖专用模型 | 多模态模型端到端理解 |
| 局限 | 需后处理还原结构 | 仍会幻觉，须人工核验 |

结合模块二已引 EvaHan2026（古文字识别评测）与 PaddleOCR，实践路径：**VLM 出结构草稿 → 传统 OCR/人工校对关键字段 → 低置信回退人工**。这正是 DA/T 70—2018《文书类电子档案检测一般要求》"检测内容"的落地。

> **常见误区**：以为"VLM 一键读懂"能替代档案员。实际 VLM 对印章、骑缝、批注误读率仍高，关键字段须双人校对并保留"原件—VLM 输出—人工订正"记录。

**实践流程**：
1. 取一张民国公文扫描件；
2. 分别用 PaddleOCR 与 Qwen-VL 转写；
3. 对比表格还原度与错字率；
4. 写"本馆 OCR 选型建议"（何时 VLM、何时传统 OCR）。

**评估要点**：是否给出可操作的选型判据而非泛泛而谈。

# 复现本节课的文献检索（均为免费开放 API，无需密钥）
import urllib.request, urllib.parse, json
q = 'document image understanding OCR historical documents handwriting'
# 1) OpenAlex：开放学术图谱（聚合期刊/会议/预印本，含被引数）
url_oa = "https://api.openalex.org/works?search=" + urllib.parse.quote(q) + "&per_page=10&sort=cited_by_count:desc"
oa = json.loads(urllib.request.urlopen(url_oa, timeout=30).read())
for w in oa["results"]:
    print("OA", w["publication_year"], w["title"], "->", (w.get("primary_location") or {}).get("source", {}).get("display_name"))
# 2) CrossRef：期刊 DOI 元数据（代表期刊网站 / 电子期刊，可溯到出版社原文）
url_cr = "https://api.crossref.org/works?query=" + urllib.parse.quote(q) + "&rows=10"
cr = json.loads(urllib.request.urlopen(url_cr, timeout=30).read())
for it in cr["message"]["items"]:
    print("CR", (it.get("issued",{}).get("date-parts",[[""]])[0][0]), (it.get("title") or [""])[0])
```
