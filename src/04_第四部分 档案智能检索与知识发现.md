## 第四部分　档案智能检索与知识发现

> **学习目标**
> - 知识：区分关键词检索与语义检索；理解知识图谱的"实体—关系—属性"三元组模型；掌握关联分析的基本思路。
> - 能力：能设计一个档案知识图谱的构建流程；能用自然语言查询获得语义检索结果。
> - 素养：认识"检索即解释"——检索结果的排序与呈现本身带有立场；理解知识发现对隐性关联的揭示价值与误读风险。

### 4.1　从关键词检索到语义检索

- **关键词检索（布尔/倒排索引）**：精确但僵硬，"土地改革"查不到"土改""查田定产"，依赖用户掌握同义词。
- **语义检索（向量检索）**：把查询与文档都映射为向量，按语义相似度排序。用户问"建国初期怎么处理地主土地？"可命中"土地改革""减租减息"等相关档案。
- **混合检索**：关键词保证精确，语义保证召回，二者融合是业界主流。

**实践示例（语义检索的向量相似度）**：

```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
query = model.encode("建国初期如何处置地主土地")
docs  = model.encode([
    "1950年颁布《土地改革法》，没收地主土地分给无地农民",
    "某县1951年春耕生产总结",
    "土地改革中对工商业者兼营土地的政策说明",
])
sims = np.dot(docs, query) / (np.linalg.norm(docs,axis=1)*np.linalg.norm(query))
top = np.argsort(-sims)[:2]
print([docs[i] for i in top])  # 返回与查询语义最相关的档案
```

### 4.2　档案知识图谱构建

知识图谱用**三元组（实体—关系—属性）**组织知识，例如：`(邓小平, 签发, 关于教育改革的指示)×(指示, 形成于, 1985年)`。

**构建流程**：
1. **实体识别（NER）**：从档案文本抽出人物、机构、地点、事件、文件名。
2. **关系抽取**：识别实体间关系（任职于、签发、隶属于、参与）。
3. **实体消歧与链接**：把"李鹏（总理）"与"李鹏（同名科员）"区分，链接到规范知识库。
4. **图谱存储与查询**：用图数据库（Neo4j）存储，Cypher 查询。

**实践示例（用 networkx 构建小型档案关系图）**：

```python
import networkx as nx
G = nx.DiGraph()
G.add_edge("邓小平", "签发", )  # 简化示意
G.add_node("关于教育改革的指示")
G.add_edge("邓小平", "关于教育改革的指示", label="签发")
G.add_edge("关于教育改革的指示", "1985年", label="形成于")
# 查询"邓小平签发了哪些文件"
issued = [t for s,e,t in G.edges("邓小平", data=True) if t.get("label")=="签发"]
print(issued)
```

> **智能交互（检索差异演示）**：学生输入同一自然语言查询，系统并排展示"关键词检索结果"与"语义检索结果"，AI 标注两者差异与各自的盲区，直观理解技术选择的后果。

### 4.3　关联分析与知识发现

知识图谱的真正价值在于**发现隐性关联**：
- **人物—事件—机构网络**：揭示某历史事件中参与者、决策机构、关联文件的整体结构。
- **社区发现**：在交游/公务网络中识别核心群体。
- **时序演化**：观察机构、人物关系的随时间变化。

**误读风险**：关联不等于因果。"A 与 B 同现于多份档案"可能只是同期任职，未必有实质合作——知识发现必须回到档案原境验证。

> **讯飞知喻实践（专栏）**：讯飞知喻的知识图谱能力在档案场景中支持实体识别、关系抽取与知识推理，可将分散在多全宗的档案自动织成"事件—人物—机构"关联网络，辅助查档与编研。课堂可演示一个"某重大工程"档案如何从孤立文件变为可问答的知识网络。

### 4.6 档案知识图谱 + 大模型问答（GraphRAG）（V2.0）

检索不止"关键词"，更能"问答推理"。V2.0 引入知识图谱与大模型融合的 GraphRAG（来源：数据要素库《阿里数字商业知识图谱构建及开放》、最全行业报告《基于知识图谱的工业自动化知识发现》、DH 库贾君枝《知识组织》）：

- **档案知识图谱**：把"人物—机构—事件—文件"连成图，支持"邓小平签发了哪些文件"类多跳查询。
- **GraphRAG**：检索时先取子图、再让大模型基于子图作答，比纯向量 RAG 更擅长关系型问题。

| 方式 | 擅长 | 不擅长 |
|---|---|---|
| 关键词检索 | 精确匹配 | 关系推理 |
| 向量 RAG | 语义相似 | 多跳关系 |
| GraphRAG | 关系/多跳 | 需先建图 |

> **为什么重要**：档案价值常藏在"关系"里（谁经手、谁签发、关联哪起事件）。图谱让隐性关系显性化。

**实践流程**：
1. 用模块四关系数据建小知识图谱；
2. 提问"复社成员中谁同时与两位意见领袖交往"；
3. 对比图谱查询与全文检索答案质量；
4. 讨论建图成本与收益。

**评估要点**：是否说明 GraphRAG 依赖"图质量"，垃圾进垃圾出。


### 4.7 案例精读：用 GraphRAG 回答"某工程涉及哪些部门"（V2.0 续）

**背景**：把 4.6 的图谱落到真实查档场景。

**课堂复现（检索即方法）**：下列代码展示如何直接调用 OpenAlex 与 CrossRef 的免费 API 复现本模块文献检索，强调"可溯源"的研究习惯（无需任何密钥）。

```python
# 复现本节课的文献检索（均为免费开放 API，无需密钥）
import urllib.request, urllib.parse, json
q = 'knowledge graph retrieval augmented generation archives semantic search'
# 1) OpenAlex：开放学术图谱（聚合期刊/会议/预印本，含被引数）
url_oa = "https://api.openalex.org/works?search=" + urllib.parse.quote(q) + "&per_page=10&sort=cited_by_count:desc"
oa = json.loads(urllib.request.urlopen(url_oa, timeout=30).read())
for w in oa["results"]:
    print("OA", w["publication_year"], w["title"], "->", (w.get("primary_location") or {}).get("source", {}).get("display_name"))
# 2) CrossRef：期刊 DOI 元数据（代表期刊网站 / 电子期刊，可溯到出版社原文）
url_cr = "https://api.crossref.org/works?query=" + urllib.parse.quote(q) + "&rows=10"
cr = json.loads(urllib.request.urlopen(url_cr, timeout=30).read())
for it in cr["message"]["items"]:
    print("CR", (it.get("issued",{}).get("date-parts",[[""]])[0][0]), (it.get("title") or [""])[0])
```

**误用警示**：① 预印本（arXiv）未经同行评审，引用时须标注"preprint"并追踪正式版本；② 被引数仅代表影响力而非结论正确，须回到原文核对方法与数据；③ 商业数据库（Web of Science、Scopus、Elsevier、JSTOR、CNKI 知网、万方、维普等）本环境无订阅权限，无法直连，需通过机构账号在本地获取后再贴入；④ 文献与本节实验的映射是"启发"而非"背书"，落地前需在教材预部署环境中实测。
